### Shipping

**land するものを自分が持つ。各 PR を独立に verify、verified run は root からだけ land、その後 queue に手を出さない。**

`playbooks/babysit.md` の後半。

1. **forge を resolve し、全 PR を独立に verify。** GitHub CLI（`gh`）が default。`command -v origin` が成功し Origin が repo を解決できるなら PR view、watch、edit、merge に `origin pr ...`。なければ `gh` に留まり fallback を記録。Graphite（`gt`）は要求しない。PR あたり 1 subagent、batch しない。各々 Cursor cloud agent。real surface を matching control skill（`cursor-team-kit` の `control-ui` や `control-cli` 等）で parent vs head に対して exercise。各々 `PASS`、`PASS+NOTES`、または `FAIL` を返し、その verdict を自分の PR に post。Safe は code を書かなかった agent からの verdict。CI green は verdict ではない。approving bot review も verdict ではない。
2. **bottom で root した contiguous verified run だけ land。** 最下 unmerged PR から上へ歩き、passing verdict のない最初の PR で stop。`PASS` と `PASS+NOTES` は両方 pass。unverified の下に verified PR があっても landable ではない。ceiling を PR number で report し chain を壊すものを言う。
3. **各 verdict がまだ patch を述べているか再確認。** verdict head SHA、base SHA、その PR の base-to-head diff の stable `git patch-id` を記録。rebase や base retarget は SHA を書き換え、check に触れず verdict を無効化しうる。land 前に記録 patch-id と現在の base-to-head patch-id を比較。2 patch が test、docs、lint config だけ違うとき、各 lane が走らせたものを build。verdict SHA で 2 回、current head で 1 回。差は verdict SHA で 2 build も示すか embedded commit SHA なら noise。file ではなく各 difference を judgeし、noise 各 kind と file を report。noise だけ違うならその lane の結果は valid。checks と change の review は fresh。dev server や build output のないものから lane result を reuse しない。その lane を rerun。patch が変わったら他も re-verify。変わらなければ code verdict は keep、current head で mergeability と CI を再実行。古い SHA の一致 commit message や green check を substitute にしない。
4. **bottom PR だけ prepare。** current trunk を fetch。要れば lowest verified branch を exact trunk tip に rebase、push、`origin pr edit <pr> --base <trunk>` か `gh pr edit <pr> --base <trunk>` でその PR だけ trunk に retarget。push 後 step 3 を再実行。descendant はまだ retarget、arm、merge しない。
5. **PR を 1 つずつ land。** bottom PR が今 mergeable なら `origin pr merge <pr> --squash` か `gh pr merge <pr> --squash`。requirements がまだ走り user が merge-when-ready を求めたならその PR だけ `origin pr merge <pr> --squash --auto` か `gh pr merge <pr> --squash --auto` で arm。Origin の `--auto` は Origin merge-when-ready。GitHub の `--auto` は GitHub auto-merge。次を prepare する前にその PR の merge を待つ。
6. **GitHub `autoMergeRequest` を stack readiness と読まない。** 多くとも 1 GitHub PR に GitHub auto-merge が要求されたこと。Origin merge-when-ready が arm 済み、descendant が queued、patch verdict が current、contiguous stack が safe を証明しない。current bottom PR の active forge state を確認。active forge が報告できなければ state unknown と言う。
7. **各 merge の後に recompute。** trunk fetch、merged SHA の存在確認、frozen bottom-to-top list から merged PR を drop、新 bottom PR の base、head、checks、patch-id を inspect。host が child を自動 retarget しうるが assume しない。その 1 PR で step 3–6 を repeat。独立 work はこの chain 外で独自に ship。
8. **current frontier が merge か fail まで watch。queue 周りを mutate しない。** Origin では `origin pr view <pr> --checks --comments` と `origin pr checks <pr> --watch`、merged か blocked まで PR を再読。GitHub では `scripts/watch-pr/watch-pr --queued-stack --stack-prs <bottom>` は event wake だけ。各 wake 後 `gh pr view <pr> --json state,mergedAt,mergeStateStatus,statusCheckRollup,autoMergeRequest` を poll。`mergedAt` が non-null か `state` が `MERGED` まで `READY` を無視。その後だけ step 7。`state` が `CLOSED` で `mergedAt` なし、required check が `FAILURE` か `CANCELLED` で auto-merge pending 後 merge を block、または `mergeStateStatus` が `UNSTABLE` か `DIRTY` で auto-merge pending なしのときだけ hard-fail。checks pending か auto-merge armed の `BLOCKED` は failure ではない。Babysit の queued `WAITING`/`merge-queue` stop condition はここでは使わない。watch は `/loop` dynamic mode で hold。各 merge と新 ceiling を report。queue が stall なら mutate 前に diagnose。
9. **ceiling で stop。** verified run が merge 済みなら land したもの、次の unverified PR、verify に何が要るかを report。run を延ばすのは step 1 の新 pass。

**Reply:** verified run と ceiling、各 PR の verdict と producer、arm したものと確認方法、land したもの、次の gap に要るもの。
