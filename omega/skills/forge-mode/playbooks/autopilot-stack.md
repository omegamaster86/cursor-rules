### Autopilot-stack

**stack を自分が持ち、landing は never。queue を full autonomy で build と verify し、operator に review と land 用の 1 本の linear base-branch stack を渡す。** **Autopilot-full** の sibling。

1. **owner loop はそのまま。** program 用に forge を 1 回 resolve。GitHub CLI（`gh`）が default。`command -v origin` が成功し Origin が repo を解決できるなら PR create、edit、view、watch、merge に `origin pr ...`。なければ `gh` に留まり fallback を記録。Graphite（`gt`）は要求しない。PR あたり 1 Cursor cloud agent が change を end-to-end own: build、first push、self-proof 前に ready PR、self-proof（gates、CI、receipts）、`../references/bugbot-triage.md` に従う skeptical Bugbot triage、`deslop`（`cursor-team-kit` plugin の `deslop` skill（`/deslop`））、`/no-comments`（**no-comments** skill）、`playbooks/babysit.md` に従う green まで babysit。work が self-contained なら owner は parallelize。約 15 分以内に各 owner は **decision-log** skill に従い `decisions.tsv` trail を開始、first branch snapshot を push、PR を ready で開く（draft never）。その後 owner は verifiable unit ごとに branch を再 push（hooks on、WIP commit は可）。trail は uncommitted、report で返す。owner は Autopilot-full step 2 の `children.tsv` も維持。
2. **real loop で audit。** root は 1 時間ごとに audit tick。operator の go で root は Autopilot-full step 6 に従いこの tick を走らせる prompt で `/loop 1h` を arm。cadence を memory や lossy completion notification に任せない。各 tick で trunk から `git show origin/main:.cursor/skills/forge-mode/playbooks/autopilot-stack.md` でこの playbook を再読し、operation を audit。その tick で drift を fix。各 owner に generic liveness か status check で probe。side effect だけを progress と数える: commit、push、PR か check delta、store report。expected runtime を過ぎて side effect がない lane は stuck。即 stand down し replacement を dispatch。polite return を待たない。全 subagent を probe し Autopilot-full step 6 に従って tick を終える。
3. **operator gate を hold。** state-then-wait。plan を述べる依頼は go ではない。operator の stop で全 owner は即 zero-writes hold。
4. **各 round を verify。** owner は shipped code が final になったら code-ready head SHA を 1 回 report。loop が green なら STACK-READY と exact head SHA。root は Autopilot-full step 4 に従い各 round を verify。merge-ready の代わりに STACK-READY。unverified は stack に入れない。
5. **clean verdict で append、ship は never。** owner は merge、auto-merge arm、close しない。clean verdict は verified order、または operator が指定した order で 1 本の linear base-branch stack に PR を append。
6. **topology は single writer、build は parallel writer。** owner は自分の branch だけ push し tip、current base、intended parent を report。root だけが topology writer。PR を append するには intended parent を fetch、child branch をその exact parent tip に rebase、`ls-remote` check の後だけ `--force-with-lease` で push、PR base を parent branch に。resolved forge に従い `origin pr create --status open --base <parent-branch>` か `gh pr create --base <parent-branch>` で create。既存 PR は `origin pr edit <pr> --base <parent-branch>` か `gh pr edit <pr> --base <parent-branch>` で retarget。root PR だけ trunk を target。`gt` で chain を submit や register しない。
7. **drift は root で absorb、その後動いたものを re-verify。** root は current trunk を fetch し chain を bottom から top に rebase。rebase が owner の file で conflict を出したら owner が自分の slice を fix し root が result を push。rebase は上の全 SHA を書き換え古い SHA の verdict を void。各 verdict SHA で `playbooks/shipping.md` の patch-id rule を適用。もはや valid でないものは delivery 前にこの playbook の step 4 に戻す。patch-id が unchanged でも rewritten push の後は mergeability と CI を再実行。countersign rule は Autopilot-full と同じ。genuinely new pin は root の fresh countersign で stop を raise。land 済み value の drift absorb は raise ではない。
8. **chain を deliver。** deliverable は verified PR の 1 本の linear chain。resolved forge で bottom-up に review 可能。各 link は PR body か comment に verifier verdict。operator が review し land。自分の click か merge-when-ready の arm。

**autopilot の選択。** PR が独立で landing authority があるなら Autopilot-full。operator が land 前に review を欲する、work が sequenced か coupled、merge authority が withhold されているなら Autopilot-stack。
