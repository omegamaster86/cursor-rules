### Autopilot-full

**verdict を自分が持ち、PR は never。PR ごとに 1 owner が build から merge まで走り、clean swarm verdict なしでは merge しない。** 「autopilot this queue」「full autopilot」、one-owner-per-PR program 向け。Orchestrate は coordinator が verified work を自分で land する standing program。worker は merge しない。ここでは各 PR の owner が lifecycle 全体を merge まで担い、root は verification、countersign、audit だけ。

1. **operator の item を mark し state-then-wait を honor。** operator が名指した item は operator に残る。operator が review して click。owner は merge しない。operator が protocol か plan の述べを求めたら statement を deliver して stop。execution は operator の明示 go だけで始まる。
2. **PR ごとに 1 owner を spawn。full lifecycle と early trail。** program 用に forge を 1 回 resolve。GitHub CLI（`gh`）が default。`command -v origin` が成功し Origin が repo を解決できるなら PR create、edit、view、watch、merge に `origin pr ...`。なければ `gh` に留まり fallback を記録。Graphite（`gt`）は要求しない。PR あたり 1 Cursor cloud agent が build、first push、ready PR、real artifact 上の self-proof（**prove-it-works** principle skill）、`../references/bugbot-triage.md` に従う skeptical Bugbot triage、slop-strip（`cursor-team-kit` plugin の `deslop` skill（`/deslop`））、`/no-comments`（**no-comments** skill）、current trunk への rebase、green までの babysit loop（`playbooks/babysit.md`）、merge 自体を own。約 15 分以内に各 owner は **decision-log** skill に従い `decisions.tsv` trail を開始、first branch snapshot を push、PR を ready で開く（draft never）。その後 owner は verifiable unit ごとに branch を再 push（hooks on、WIP commit は可）。self-proof 前に PR を開き URL、decisions、checks が durable trail になる。`decisions.tsv` は uncommitted、report と一緒に返す。subagent が始まったら owner は ID、expected runtime（その kind の過去 run の longest 以上）、state を同様に keep する `children.tsv` に追加。owner は code-ready report と babysit の前に最初の rebase。trunk が drift していなくても。fix round では owner はその merge base を keep。owner が再 rebase するのは merge prep（step 5）、trunk との `git merge-tree` conflict、trunk の change 由来の CI failure だけ。shipped code が final になったら slop-strip と `/no-comments` の後 code-ready head SHA を report。patch を変える各 later push の SHA も report。self-proof、CI、babysit は swarm と parallel。owner は self-proof、CI、babysit が finish したら merge-ready と head SHA を report。round を始める push の前に、触った path に対して repo の AGENTS.md と rules が名指す pre-review checks。committed head で実行。hook pass は proof ではない。各 rebase を publish するには `ls-remote` check の後 owner 自身の branch を `git push --force-with-lease`。shared branch を force-push しない。merge は owner が単独で取れない唯一の step。step 4 が gate。
3. **owner を true parallel で走らせ、stack しない。** PR が self-contained なら多数同時: branch あたり 1 writer、disjoint files、cross-PR drift は rebase で absorb。本当に overlap する work だけ serialize。self-contained PR は main から straight branch。sequenced work は merge-then-branch。1 例外: genuinely dependent change を split しなければならない owner は短い private base-branch stack を hold しうる。
4. **各 round の merge 前に swarm-verify。** round は owner の code-ready head SHA と patch を変える各 later push で始まる。その SHA で **swarm** skill に従い parallel independent verifier に fan out し 1 verdict に aggregate。merge には merge-ready head と patch が一致する round の clean verdict が要る。merge-ready report の receipt を verdict 前に audit。lane: その SHA で gate を再実行。change が触る real surface で load-bearing behavior を live prove（matching control skill、`cursor-team-kit` の `control-cli` か `control-ui`、または無ければ named driver）。diff を audit、PR body を distrust。audit は full brief で 2 以上の review lane。**Regression lane against trunk。** current trunk で同じ load-bearing scenario。trunk に feature がなければその fact を記録し、diff が足す behavior と user が待つ end state を gate。trunk が出せるふりをしない。live lane が floor。それなしの verdict は clean ではない。root の clean verdict なし merge なし。lane が返ったら proven finding を 1 fix-forward で owner に送る。lane が note と filed した defect も finding。behavior finding ごとに同じ defect の全 site を cover する red test を求める。test で defect を示せないなら repro receipt。次 round の review brief にその defect を追加。新 head は fresh swarm と fresh verdict。`playbooks/shipping.md` の patch-id rule で valid な lane result は除く。
5. **clean verdict で owner が merge。fresh owner が次 item。** owner は current trunk に freshly rebased した head からだけ merge。merge prep は round の lane 開始前にならない。merge 直前に current trunk への rebase で終わる。merge-prep rebase の後 owner は新 head SHA を report。その head で merge 前に CI pass。patch-id rule が round の verdict をまだ hold するか決める。その head が green で patch-id が `playbooks/shipping.md` の patch-id rule で verdict と一致したら、後の trunk move は別 rebase を強制しない。merge 直前に trunk fetch し head と current trunk の `git merge-tree` が clean か確認。`git diff --name-only $(git merge-base HEAD origin/main) origin/main` の path が PR が変える path、またはその PR にどの CI が走るか決める path（repo の CI config path 等）かも確認。どちらか fail なら再 rebase、新 head SHA report、その head で CI pass を待ち、check を repeat。新 head は patch-id unchanged でなければ verdict を void。owner は resolved forge で自分の PR を squash-merge して return。fresh owner が queue から次の self-contained item（forge-mode の Subagents section）。operator の full-autonomy grant と root の clean verdict が babysit だけではない merge authorization。operator-named item は merge-ready で stop し operator の click を待つ。
6. **root layer を走らせる。** pinned gate か budget value の genuinely new raise（CI が tighten だけ許す limit）は verifier proof の後に grant される fresh countersign が要る。operator の grant か standing orders が approval をカバーするなら countersign が approval。owner は tool の approval contract が許す form で記録し root の countersign への pointer。lane がその countersign に対して record を check。root は forge が enforce する approval を give や bypass しない。main に既に land した value の absorb は drift で raise ではない。全 owner に 1 時間ごと audit tick。operator の go で `/loop 1h` をこの tick を走らせる prompt で arm。`/loop` は local と cloud root で動く。cadence を memory や lossy completion notification に任せない。各 tick で trunk から `git show origin/main:.cursor/skills/forge-mode/playbooks/autopilot-full.md` でこの playbook を再読し operation を audit。その tick で drift を fix。各 owner に generic liveness か status check で probe。decision trail を collect。side effect だけ progress: commit、push、PR か check delta、store report。error した lane、または expected runtime を過ぎて side effect がない lane は stuck。即 stand down し replacement dispatch。polite return を待たない。tick は step 2 が要求する pushed branch と decision trail で owner を judge。turn を開始できない agent の owner を replace。各 tick は program の agent list（platform にあれば）と全 owner の `children.tsv` で lane stuck test も実行。stop が効くかどうかに関わらず root は owner に stuck subagent を stuck と記録し、work がまだ要るなら replace。stall した各 replacement に同じ step。owner ができないとき root が両方。stall は work を prove も drop もしない。merge が batch なら retro pass と post-merge bot-comment sweep。delegated work が残らないときだけ tick を終える。最後の merge の後も。
7. **operator の stop で即 stand down。** operator の hold か stand-down は全 owner に即 zero-writes order。owner は operator が release するまで brief を hold。

**Reply:** queue と各 PR の owner、state、head SHA。各 verdict とそれを出した swarm。merge したものと各 fresh owner が次に取ったもの。grant した countersign と理由。open operator gate。collect した decision trail の場所。
