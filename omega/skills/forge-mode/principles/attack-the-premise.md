# 前提を攻撃する（Attack the Premise）

同じ前提を共有する修正が 2 回以上、同じゲートで失敗したら、修正ではなく**前提**を疑う。

**適用:** 連続した fix が同じ仮定の上で再び失敗するとき。次の fix の前に、どのアクターが不均衡を抱えているか **census** を取る。

**理由:** 共有前提の下での失敗は、前提についての証拠である。

**パターン:**
- **前提を 1 文で書く。** 失敗した fix がすべて暗黙に信じていた文
- **次の fix の前に census。** アクターごとの不均衡を数える（大きさではなく誰が偏っているか）。再実行可能なスクリプトにする（`build-the-lever.md`）
- **偏りを読む。** 毎回同じ少数のアクターが不均衡の大半なら、役割を割り当てている何かがある。それを `fix-root-causes.md` で辿る
- **補償ではなく非対称を除去する**（`laziness-protocol.md`）。役割のローテーション、割当のランダム化、役割の移動。毎 run で同じアクターだけが負荷を持つ設計を残さない

**止める:**
- 前提が書かれ、census がある前に次の fix を始めない
- census がアクター間で均等なら、前提が原因ではない。別原因を探し、census は証拠として残す

**区別:** `redesign-from-first-principles.md` は新要件で設計を組み直す。本原則は**現設計が真だと仮定している事実**を疑う。
