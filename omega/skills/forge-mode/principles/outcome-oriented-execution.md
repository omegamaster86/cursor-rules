# 最終形に収束する

計画された rewrite / 移行では、途中を全部安定させることより、意図した検証可能な最終形に最適化する。

**適用:** フェーズ境界が明示された rewrite・移行（モック→実 API、層の入れ替え、フラグ付き切替の完了）。日常の小さな Feature / Bug-fix では読まない。

**理由:** 中間ステップを常に完全安定にしようとすると、一時互換コードが長期の負債になる。目標アーキテクチャへ収束し、明示した検証境界で正しさを証明する。

**コア:**
- 移行の滑らかさより最終形の整合を優先する
- 計画され、スコープ付き、可逆なら、途中の壊れは許容する
- 完了宣言の前に最終検証を必ず走らせる（正本は **`/verify-done`**）

**ガードレール:**
- 一時的な壊れが許容される場所を宣言する
- 触っている領域の高信号チェックは移行中も残す
- プラン完了時に静的 + ランタイムの検証を要求する
- 捨てる前提の橋（二重実装、期限のない Feature Flag、旧パス並存）をデフォルトにしない

**既存との差:** `sequence-verifiable-units.md` は小さく切って毎回検証する。本原則は、切った単位の中で throwaway な互換を増やしすぎない。両立する。単位は検証可能、橋は恒久化しない。
