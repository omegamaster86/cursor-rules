# 足す前に引く（Subtract Before You Add）

システムを進化させるとき、**先に複雑さを削り、後から足す。**

**適用:** 追加・リファクタ・rewrite の順序を決めるとき。

**理由:** 複雑な土台に足すと複雑さが複利になる。先に削るとコードが減り、本質構造が見え、次の設計が自明になりやすい。

**パターン:**
- 削除を構築より先に sequence する
- 磨く前に切る（最小形にしてから品質投資）
- 観測された用法のために設計し、投機的 edge case のためではない
- spec が要求しない検証・パーサ・ガードは置かない
- 冗長な指示・過剰テンプレートはプロンプトから削る
- 新規性のない参照は stub を残さず削除

**投資:** 同じか smaller な表面の向こうに、見つけた時より少し単純で capable な設計を残す。
