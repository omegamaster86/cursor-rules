# 根本原因を直す

デバッグでは症状の場所ではなく、システムが初めて誤ったことを起こした（または扱うべき状態を扱えなかった）**最初の場所**を直す。症状は誤った状態が見えた場所。根本原因はその手前。

**理由:** 症状直しは証拠を隠し、故障は別の場所に出る。誰も名指ししていないバグのワークアラウンドが積み上がり、推論が難しくなる。

**パターン:**
- 先に再現する
- 答えが「さらに前の結果」ではなくコードの誤った判断になるまで「なぜ」を繰り返す
- 行き詰まったら計装する。実際のエラーと実際の state を読む。推測しない
- 症状を起こした state が**正当**か問う。システムがその state にありうるなら、そこで壊れたコードが根本原因であり、state をそこで扱うのが fix。state が存在すべきでないなら、壊れた場所のチェックはバグを隠す。state を生んだものを探す。guard、retry、握りつぶしエラー、clamp、捨てた state が典型
- 再起動後だけ失敗するなら、まず永続 state（config、cache、lock、シリアライズ）を疑う
- インスタンスだけでなくパターンを見る。同じ故障のある場所をすべて直す
- 正当化に段落のコメントが要るならコードが間違い（コメントではなくコード）
- 決め手の fact を深掘りしたなら、最初から見えていた安い常時 signal を提案する

手順・再現・verify の順序は `playbooks/bug-fix.md`。完了証明は **`/verify-done`**。
