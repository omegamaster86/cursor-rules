# 根本原因を直す

デバッグでは症状を糊で覆わない。問題を根本原因まで辿り、そこで直す。手順の骨格は Bug-fix プレイブック。本ファイルは **症状直しを禁止する判断**。完了証明は **`/verify-done`**。

**理由:** 対症療法は積み上がる。ワークアラウンドが増えるほど推論しにくくなり、本物のバグは残る。根本原因の修正は最初は遅いが、デバッグの総時間は減る。

**パターン:**
- 先に再現する（再現できない修正は検証できない）
- 「なぜ」を根本まで繰り返す
- crash を黙らせる nil-check / ガードを足す衝動に抗う（それは症状直し）
- 正当化に段落のコメントが要るならコードが間違い（コメントではなくコードを直す）
- インスタンスだけでなくパターンを見る（同じ形を grep し、該当をすべて直す）
- 行き詰まったら推測しない。計装し、実際のエラーを読む

**再起動バグはコードより state を疑う**

実行のあいだコードは変わらない。変わるのは state である。「再起動すると壊れる」なら、まず古い永続状態（config、cache、lock、シリアライズ済み state）を疑う。state ファイルを消すと直るなら、修正の優先は state の検証である。

手順・再現・verify の順序は `playbooks/bug-fix.md`。
