# 怠惰プロトコル（Laziness Protocol）

最小のコードと複雑さで最大の結果を狙う。

**適用:** リファクタ、diff の大きさの判断、抽象・層・シグナル配線を足したくなったとき。

**理由:** 人間がメンテ exhausting と感じる解は悪い解である。

**パターン:**
- **削除を優先。** 改善・リファクタでは追加より先に削れるものを探す
- **呼び出し階層を浅く。** 質問に答えるのに 3 ファイル超を辿るなら flatten を検討
- **判断を一箇所に集約。** 同じ選択を複数箇所に書かず、単一の source of truth とフラグ
- **diff を最小化。** 「きれいな」ボイラープレートより少ない行数
- **配線を疑う。** 型・スキーマ・パイプラインに新シグナルを通す前に、より直接の経路を探す
- **小さな漏れを潰す。** 1 呼び出しだけの pass-through、表現の漏れ、重複した選択を早めに除去

**テスト:** 同僚がこのコードを読んで疲れるなら、まだ削れる。
