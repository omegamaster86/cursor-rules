# 読者負荷を最小化する（Minimize Reader Load）

保守性は、読者が理解のために払う作業量である。2 軸を追う:

1. **辿る層数** — 質問と答えの間の間接化
2. **保持する状態** — 読者の頭の中の hidden / mutable コンテキスト

**適用:** 追いにくいコードをレビュー・整形するとき。

**理由:** コードは書くより読まれる。LOC や cyclomatic complexity は proxy である。読者負荷が本体。`guard-the-context-window.md` の人間版 — ワーキングメモリは読者にも有限。

**パターン:**
- **層を潰す:** 呼び出し元 1 つの wrapper、第二実装のない adapter、不要な indirection
- **隣接層は抽象度を変える。** 同じメソッド引数の繰り返しだけの層は圧縮なしで負荷を増やす
- **インターフェースは圧縮を要求。** 広くて中身を隠さない API は表面と実装の両方を覚えさせる
- **状態スコープを縮める:** pure を優先、local > field > module > global。sync より derive
- **不変条件は境界で 1 回名指し** — 各 consumer で繰り返さない
- 層や state を足す前に: 別の場所の読者負荷を少なくとも同量減らすか？

**テスト:** 新規読者が「X はどこから来る？」「X は何が変えうる？」に 30 秒以内で答えられるか。否なら層か state を切る。
