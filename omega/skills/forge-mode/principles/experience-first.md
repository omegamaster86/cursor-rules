# 体験を先にする

プロダクトは体験である。技術判断は体験を助けるか損なう。実装の都合とユーザーの喜びがぶつかったら、喜びを選ぶ。

**適用:** Intent gate が alignment 済み / skip のあと、プロダクト・UX・機能スコープのトレードオフ。方向が空なら本原則ではなく **`/plan-interview`**。Align 中は使わない。

- 1000 個のことに No と言う（機能・操作・オプションはそれぞれ居場所を稼ぐ）
- 少なく、良く出す（磨いた 3 機能は粗い 10 機能に勝つ）
- 本番コードの前に prototype する（設計判断は throwaway の方が安い）
- 細部を磨く（遷移、揃え、余白、フィードバック、エラー状態）
- コアループを締める（各機能は中心ワークフローに仕えるか、道を空ける）

ユーザーは成果物を消費する人である。UI ならエンドユーザー。ライブラリや内部 API なら import する同僚。次にコードを触るエンジニアもユーザーである。その席から影響を説明する。

基盤は体験に仕える。逆ではない。**作業の順番**は `foundational-thinking.md`。本原則は **何を目指すか**。観測で決まる分岐は Prototype プレイブック（Align ではない）。
