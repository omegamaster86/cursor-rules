# Grilling

計画・意思決定・アイデアについて、共有理解に到達するまで容赦なくインタビューする。これを **設計木（design tree）** として捉える。各意思決定は、それにぶら下がる次の意思決定へ枝分かれする。

## ラウンドと frontier

木を **ラウンド** で進める。**frontier（前線）** は、前提がすでに決まった意思決定の集合 — まだ聞いていない答えを当てずに、**今この瞬間** 聞ける質問のすべて。

1 ラウンドで frontier の質問を **まとめて** 出す。各問に番号を付け、**推奨回答** を添える。ユーザーの回答を待ってから次のラウンドへ。

各質問は、推奨に「はい」で受け入れられるように書く（yes で推奨が選ばれる文言）。

ユーザーが答えると木が更新される。決まった枝が frontier を外側へ押し広げ、依存していた問が解放される。frontier を再計算し、次のラウンドへ。このラウンドでまだ開いている別の問に答えが依存する問は、**次のラウンド** に回す（同じラウンドに混ぜない）。

### 1 ラウンドの書式

```
❓ **Q1** - **<問いの短い題>**: <本文。複数段落・選択肢可>

➡️ <推奨回答>

---

❓ **Q2** - **<問いの短い題>**: <本文>

➡️ <推奨回答>
```

## 事実と意思決定

**事実**（ファイルシステム・ツール・コードベースで調べられること）はユーザーの仕事ではない。frontier の問に事実が要るなら **サブエージェント** を投げて調べる。調査中はその前提に依存する問だけ待つ。それ以外の frontier は **今のラウンドで** 聞く。

**意思決定**はユーザーのもの。各問を提示し、回答を待つ。

frontier が空になるまで続ける。木の枝を一通り踏み、暗黙の前提を残さない。ユーザーが共有理解に達したと確認するまで、計画の実行・実装・コミットは始めない。

## 終了後

合意を要約し、確認を求める。ユーザーが確認したら終了。必要なら **decision-log** へルーティング（任意）。
