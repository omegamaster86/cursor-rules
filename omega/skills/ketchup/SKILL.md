# Ketchup

ユーザーが `/ketchup` の直前に書いた最後のメッセージ以降、このチャットで起きたことをキャッチアップし、各変化の「今どこまでか」だけでなく「何が変わったか」も伝える。通知とサブエージェント結果はユーザーのメッセージではない。ユーザーは自分の最後のメッセージだけ覚えていて、その後は何も知らないと仮定する。

[`/bro`](../bro/SKILL.md) の声を使い、その restating タスクはしない。平易な言葉、短い文、専門用語なし。一人がもう一人に追いつかせる口調。ユーザーにとって何が変わったかを書き、どうやったかは書かない。「CI は green」ではなく「テストは通った」と言う。ユーザーが動くために必要なとき以外は hash、パス、コマンド、ビルド番号、テスト件数は省く。PR・branch・エージェントは作業中に付けたラベルではなく、ユーザーが知っている名前で呼ぶ。文脈がないと意味が通じない事実は文脈を付けるか、その事実ごと省く。

## 何が変わったか集める

このターンは read-only。ビジュアルは既にあるものだけから作る。コードを変え、アプリやジョブを起動し、何かを post しない。そのメッセージ以降の自分の作業、サブエージェントの報告、このチャットの他者メッセージを集める。このチャットが触れた各 PR・CI・エージェントの現状を確認する。示す数字は根拠と照合し、直したときはそう言う。

action item はユーザーだけが取れる決定またはステップ（プロダクト判断、承認、不可逆操作、アクセス不足）。ユーザー最後のメッセージより前から待っているものも含める。自分がまだできる作業は action item ではない。返信を埋めるための判断を捏造しない。ユーザーが求めておらず作業にも不要なステップは action item ではない。不可逆でユーザー待ちのものだけは action item 1 行（ビジュアルなし）。答えない場合の結果は書かない。

## 返信を書く

返信全体はビジュアルを除き 150 語以内。設計やシステムの仕組み、PR stack や依存チェーン（各 PR の状態付き）、修正の before/after、選択肢の並列など、文より図の方が伝わるときは描く。状態リストやつながりのない箱は描かない。テキストでもビジュアル間でも同じ事実を二度書かない。ユーザーに変化がなかった作業は省く。語数が足りないときは action item を削る前に「起きたこと」側を削る。

冒頭 1 文でユーザー判断が要る件数を言う。0 件ならそう言う。何も起きておらずユーザー待ちもなければそう言って終える。

次に起きたことを示す。ビジュアルを先に。作業で得たスクリーンショットと動画を本文に埋め込み、変化を説明する図があれば続ける。そのあとユーザーが求めたことごとに 1 短い bullet で要約。何になったか、完了・実行中・失敗・未確認か。声に出して言う形で書く。途中で見つけて直したバグは名指す。各行は単独で真実。action item と矛盾する完了表示はしない。要約の下に、ユーザーの知識や行動を変える行を最大 3 行。自分がまだできる残作業を 1 行。

action item は平易な bullet のみ（図や箱にしない）。各 2 行、または未依頼の不可逆だけ 1 行。決定内容と推奨と理由、そのあとユーザーが答えない場合の結果。ユーザーが持つ判断（merge、approve、選択）を聞く。自分が先に取るステップは推奨に書く。先に必要なこと、不可逆なことも推奨に含める。分からない部分は「unknown」と書く。詳細はリンクする。

リストのあと選択肢を示す。上のスクリーンショットが既に選択肢を示しているなら、各画像の下に gain と cost を書き、新しいビジュアルは描かない。そうでなければ選択肢を並べ、現状があれば含める。検討した全選択肢を載せ、各 gain と cost を書く。本文の他の部分には選択肢を混ぜない。

## ビジュアル

ビジュアルはスクリーンショット、動画、Mermaid 図、`/visualize` のチャート、生成画像。Markdown 表はビジュアルではない（before/after 列があっても）。

各ビジュアルは一目で読める大きさ。箱は最大 6、各ラベルは口に出す言葉で最大 8 語。「Tests: pass」のようなタグは使わない。文が要る事実は本文に書くか書かない。

画面に見える変化はリンクだけでなくインラインで埋め込む。見える変化なのにキャプチャが無い行は「No screenshot yet,」と書き、画面上何が変わったかを言う。持っている事実から Mermaid や `/visualize` を描く。数字を捏造しない。キャプチャしていない画面の絵を描いたり生成したりしない。存在する成果物だけリンクする。
