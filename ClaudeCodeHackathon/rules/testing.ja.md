# テスト要件

## 最低テストカバレッジ: 80%

テスト種別（すべて必須）:
1. **ユニットテスト** - 個別関数、ユーティリティ、コンポーネント
2. **統合テスト** - APIエンドポイント、DB操作
3. **E2Eテスト** - 重要ユーザーフロー（Playwright）

## テスト駆動開発

必須ワークフロー:
1. テストを先に書く（RED）
2. テスト実行 - 失敗する
3. 最小実装を書く（GREEN）
4. テスト実行 - 通る
5. リファクタ（IMPROVE）
6. カバレッジ確認（80%+）

## テスト失敗のトラブルシュート

1. **tdd-guide** エージェントを使用
2. テストの独立性を確認
3. モックが正しいか確認
4. 実装を修正（テストが正しい限り）

## エージェント支援

- **tdd-guide** - 新機能でPROACTIVELYに使用、テスト先行を徹底
- **e2e-runner** - Playwright E2Eテスト専門家
