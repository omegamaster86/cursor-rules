# コードレビュー

未コミット変更に対する包括的なセキュリティ/品質レビュー:

1. 変更ファイルを取得: git diff --name-only HEAD

2. 各変更ファイルについて以下を確認:

**セキュリティ問題（CRITICAL）:**
- ハードコードされた認証情報、APIキー、トークン
- SQLインジェクション脆弱性
- XSS脆弱性  
- 入力検証不足
- 脆弱な依存関係
- パストラバーサルリスク

**コード品質（HIGH）:**
- 50行超の関数
- 800行超のファイル
- ネスト深度が4以上
- エラーハンドリング不足
- console.logが残っている
- TODO/FIXMEコメント
- 公開APIのJSDoc不足

**ベストプラクティス（MEDIUM）:**
- ミューテーションパターン（イミュータブル推奨）
- コード/コメントの絵文字使用
- 新規コードのテスト不足
- アクセシビリティ問題（a11y）

3. 次を含むレポートを生成:
   - 重大度: CRITICAL, HIGH, MEDIUM, LOW
   - ファイル位置と行番号
   - 問題の説明
   - 修正案

4. CRITICAL または HIGH がある場合はコミットをブロック

セキュリティ脆弱性があるコードは決して承認しないこと。
