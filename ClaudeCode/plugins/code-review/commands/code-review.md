description: プルリクエストのコードレビューを行う
---

指定されたプルリクエストに対してコードレビューを実施してください。

**エージェント前提（すべてのエージェントおよびサブエージェントに適用）:**
- すべてのツールは正常に機能し、エラーなく動作します。ツールのテストや探索的な呼び出しは行わないでください。この点を起動するすべてのサブエージェントに明確に伝えてください。
- ツール呼び出しは、タスク完了に必要な場合にのみ行ってください。すべてのツール呼び出しには明確な目的が必要です。

これを行うために、次の手順を正確に実行してください:

1. 次のいずれかに該当するかを確認するために、haiku エージェントを起動してください:
   - プルリクエストがクローズされている
   - プルリクエストがドラフトである
   - プルリクエストにコードレビューが不要である（例: 自動生成 PR、明らかに正しい軽微な変更）
   - この PR に Claude がすでにコメントしている（`gh pr view <PR> --comments` で Claude によるコメントを確認）

   いずれかの条件が真であれば、そこで停止し、先へ進まないでください。

注: Claude 生成の PR は引き続きレビューしてください。

2. 関連するすべての `CLAUDE.md` ファイルについて、内容ではなくファイルパスのみを返す haiku エージェントを起動してください。対象は以下を含みます:
   - ルートの `CLAUDE.md`（存在する場合）
   - プルリクエストで変更されたファイルを含むディレクトリにある `CLAUDE.md`

3. プルリクエストを確認し、変更内容の要約を返す sonnet エージェントを起動してください。

4. 変更を独立にレビューするため、4 つのエージェントを並列で起動してください。各エージェントは問題の一覧を返し、各問題には説明と指摘理由（例: 「CLAUDE.md 準拠違反」「バグ」）を含めてください。各エージェントの役割は以下です:

   エージェント 1 + 2: CLAUDE.md 準拠チェック用 sonnet エージェント
   並列で変更を監査し、CLAUDE.md 準拠を確認します。注: あるファイルの CLAUDE.md 準拠を評価する際は、そのファイルと同じパス上または親ディレクトリにある CLAUDE.md のみを考慮してください。

   エージェント 3: Opus バグ検出エージェント（エージェント 4 と並列サブエージェント）
   明らかなバグをスキャンします。追加コンテキストは読まず、diff 自体のみに集中してください。重大なバグのみを指摘し、些細な指摘や誤検知の可能性が高いものは無視してください。git diff 外のコンテキストを見ないと検証できない問題は指摘しないでください。

   エージェント 4: Opus バグ検出エージェント（エージェント 3 と並列サブエージェント）
   追加されたコードに存在する問題を探します。セキュリティ問題、誤ったロジックなどが該当します。変更されたコードの範囲内の問題のみを対象にしてください。

   **重要: 必要なのは HIGH SIGNAL な問題のみです。** 次の条件に当てはまる問題のみを指摘してください:
   - コードがコンパイルまたはパースに失敗する（構文エラー、型エラー、import 不足、未解決参照）
   - 入力に関係なく確実に誤った結果になる（明確なロジックエラー）
   - 破っている正確なルールを引用できる、明確で曖昧さのない CLAUDE.md 違反

   次は指摘しないでください:
   - コードスタイルや品質に関する懸念
   - 特定の入力や状態に依存する潜在的問題
   - 主観的な提案や改善案

   問題が実在するか確信が持てない場合は指摘しないでください。誤検知は信頼を損ない、レビュアーの時間を浪費します。

   また、上記に加えて、各サブエージェントには PR のタイトルと説明を渡してください。著者の意図を把握するためのコンテキストとして役立ちます。

5. 手順 4 でエージェント 3 と 4 が見つけた各問題について、問題を検証する並列サブエージェントを起動してください。これらのサブエージェントには、問題の説明とあわせて PR のタイトルと説明を渡します。エージェントの役割は、その問題が本当に高い確度で問題であるかを確認することです。例えば「変数が未定義」が指摘された場合、その主張が実際にコード上で真であるかを検証します。CLAUDE.md 問題の例では、違反したルールが当該ファイルに適用されるスコープかつ実際に違反しているかを確認します。バグやロジック問題には Opus サブエージェント、CLAUDE.md 違反には sonnet エージェントを使用してください。

6. 手順 5 で検証されなかった問題を除外してください。この手順でレビュー対象となる high signal な問題一覧が確定します。

7. レビュー結果の要約をターミナルに出力してください:
   - 問題が見つかった場合、各問題を簡潔に説明して列挙してください。
   - 問題が見つからなかった場合、次を出力してください: `No issues found. Checked for bugs and CLAUDE.md compliance.`

   `--comment` 引数が指定されていない場合は、ここで終了してください。GitHub コメントは投稿しないでください。

   `--comment` 引数が指定され、かつ問題が見つからなかった場合は、`gh pr comment` を使って要約コメントを投稿して終了してください。

   `--comment` 引数が指定され、かつ問題が見つかった場合は、手順 8 に進んでください。

8. 投稿予定のコメント一覧を作成してください。これは自分用の確認目的のみです。この一覧はどこにも投稿しないでください。

9. 各問題に対して `mcp__github_inline_comment__create_inline_comment` を使い、インラインコメントを投稿してください。各コメントでは:
   - 問題の簡潔な説明を記載する
   - 小さく自己完結した修正の場合は、コミット可能な suggestion ブロックを含める
   - 大きな修正（6 行以上、構造変更、複数箇所にまたがる変更）の場合は、suggestion ブロックなしで問題点と修正案を説明する
   - suggestion のコミットだけで問題が完全に解決する場合を除き、コミット可能な suggestion を投稿しない。追加手順が必要なら、コミット可能な suggestion は残さない

   **重要: 一意な問題ごとにコメントは 1 件だけ投稿してください。重複コメントは投稿しないでください。**

手順 4 と 5 で問題評価を行う際は、次の一覧を使用してください（これらは誤検知なので、指摘しないこと）:

- 既存の問題
- バグに見えて実際には正しいもの
- シニアエンジニアが指摘しないような細かすぎる揚げ足取り
- linter が検出する問題（確認のために linter を実行しないこと）
- 一般的なコード品質の懸念（例: テストカバレッジ不足、一般的なセキュリティ問題）。ただし CLAUDE.md で明示的に要求される場合は除く
- CLAUDE.md に記載があっても、コード上で明示的に無効化されている問題（例: lint ignore コメント）

補足:

- GitHub とのやり取りには gh CLI を使用してください（例: PR の取得、コメント作成）。web fetch は使用しないでください。
- 開始前に TODO リストを作成してください。
- インラインコメントでは、各問題について必ず根拠を引用し、リンクを付けてください（例: CLAUDE.md を参照する場合はそのリンクを含める）。
- 問題が見つからず `--comment` 引数が指定されている場合は、次の形式でコメントを投稿してください:

---

## Code review

No issues found. Checked for bugs and CLAUDE.md compliance.

---

- インラインコメントでコードへのリンクを貼る際は、Markdown プレビューが正しく表示されるよう、次の形式を厳密に守ってください: https://github.com/anthropics/claude-code/blob/c21d3c10bc8e898b7ac1a2d745bdc9bc4e423afe/package.json#L10-L15
  - 完全な git sha が必要
  - 必ずフル SHA を指定してください。`https://github.com/owner/repo/blob/$(git rev-parse HEAD)/foo/bar` のようなコマンドは、コメントが Markdown で直接レンダリングされるため動作しません。
  - リポジトリ名はレビュー対象のリポジトリと一致している必要があります
  - ファイル名の後に `#` を置く
  - 行範囲は `L[start]-L[end]` 形式
  - コメント対象行を中心に、前後少なくとも 1 行のコンテキストを含める（例: 5-6 行目にコメントするなら `L4-7` へリンク）
