# Next.js Code Review

PRの差分を規約に基づいてレビューし、問題点と改善提案をフィードバックする。

## When to Apply

- PRのコードレビューを依頼された時
- コード変更の品質チェックを依頼された時
- 「レビューして」「チェックして」と言われた時

## Review Workflow

### Step 1: 差分を取得

```bash
# PRの差分を取得
gh pr diff <PR番号>

# または現在のブランチの差分
git diff main...HEAD
```

### Step 2: 変更ファイルを分類

変更ファイルを以下のカテゴリに分類し、優先度順にレビューする：

| 優先度 | カテゴリ | ファイルパターン |
|--------|----------|------------------|
| 1 | Server Actions | `_actions/*.ts` |
| 2 | API クライアント | `_apis/*.server.ts` |
| 3 | ページ | `page.tsx`, `layout.tsx` |
| 4 | コンポーネント | `_components/**/*.tsx` |
| 5 | 型定義 | `types/*.ts` |
| 6 | その他 | `_utils/`, `utils/`, `services/` など |

### Step 3: カテゴリ別レビュー

各ファイルを読み込み、[checklist.md](checklist.md) の観点に沿ってレビューする。
優先度順: A. セキュリティ（CRITICAL） → B. アーキテクチャ → C. Server Actions → D. フォーム → E. ログ → F. TypeScript → G. スタイリング → H. 命名規則

### Step 4: フィードバック出力

以下のフォーマットでフィードバックを出力する：

```markdown
## PR レビュー結果

### 概要
[変更内容の要約を1-2文で]

### 指摘事項

#### 🔴 Critical（マージ前に修正必須）
- **[ファイル名:行番号]** [指摘内容]
  - 理由: [なぜ問題か]
  - 修正案: [具体的な修正コード]

#### 🟡 Warning（改善推奨）
- **[ファイル名:行番号]** [指摘内容]
  - 修正案: [具体的な修正コード]

#### 🟢 Info（任意の改善）
- **[ファイル名:行番号]** [指摘内容]

### 良い点
- [規約に沿った実装を評価するコメント]
```

**重大度の基準：**

| レベル | 基準 | 例 |
|--------|------|-----|
| 🔴 Critical | セキュリティリスク、データ損失、アーキテクチャ違反 | `getSession()` のみで認証、3層構造の無視 |
| 🟡 Warning | 規約違反、保守性の低下 | ログ未実装、Zod未使用、不要な `"use client"`、非入力値を hidden 送信 |
| 🟢 Info | 軽微な改善提案 | 命名改善、コード簡略化 |
