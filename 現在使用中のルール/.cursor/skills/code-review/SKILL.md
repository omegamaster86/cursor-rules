# コードレビュー

## レビュー観点

### 1. 機能性
- 要件を満たしているか
- エッジケースの考慮
- エラーハンドリングの適切さ

### 2. 可読性
- 命名が明確か
- 関数/クラスの責務が単一か
- コメントが適切か

### 3. 保守性
- 重複コードがないか
- 適切な抽象化レベルか
- テストが書きやすい構造か

### 4. パフォーマンス
- 不要な再レンダリングがないか
- N+1 問題がないか

### 5. セキュリティ
- 入力値のバリデーション
- 認証・認可の確認

## コメントの書き方

```
[Must] 〇〇の理由で修正が必要です。
[Should] 〇〇の観点から、△△への変更を推奨します。
[Nit] 細かい点ですが、〇〇の方がより良いかもしれません。
[Q] この実装の意図を教えてください。
[Good] この実装は〇〇の点で優れています！
```

## 出力フォーマット

```markdown
# コードレビュー結果

## 概要
[変更内容の要約と全体的な評価]

## 良い点
- [称賛すべき実装]

## 指摘事項
### Must（必須修正）
### Should（推奨修正）
### Nit（軽微な提案）

## 質問

## 総評
```
