# Gitコミットメッセージの書式ルール

このルールは、すべてのコミットに対して適用されるコミットメッセージのガイドラインです。
またコミットメッセージ作成後に、単体テストを作成してください。

## 基本フォーマット（必須）

```
<日本語サマリ（命令形/簡潔に）>

- 変更内容1（箇条書き）
- 変更内容2（箇条書き）
- ...

## サマリ（1行目）
- 日本語で簡潔に。末尾の句点は不要。
- 何を・なぜ（必要なら）を短く表現。

## 本文（箇条書き）
- 変更点を「- 」ではじめる箇条書きで列挙。
- 原則として日本語。必要に応じて技術用語は英単語可。
- 可能なら「影響範囲」「移行手順」「リスク」「ロールバック方法」等も箇条書きで追記。

## 例

```
Bedrockの無効モデルID検知を拡張

- ResourceNotFoundException を無効ID判定に追加
- 一次/フォールバック判定の双方に適用
- リトライスキップの網羅性を向上

```

## 作業範囲
このコマンドは以下の作業までを実行します：
1. ステージされたファイルの内容を確認
2. ステージされたファイルの内容に対して単体テスト作成するために.cursor/commands/test.mdを読み込んでください
3. .cursor/commands/test.mdに則り変更内容に基づいて単体テストを作成
4. 作成したテストファイルに対して.cursor/commands/rules-check.mdを実施し、差分があれば修正
5. テストを実行し、全てpassすること
6. 変更内容に基づいてコミットメッセージを生成します
7. 開発者にコミットメッセージの確認依頼

**注意**: 
コミット（`git commit`）は含まれません。必要に応じて手動で実行してください。

## 禁止事項
- 英語だけのサマリ（原則日本語で記述）
- 曖昧なサマリ（例: "update", "fix bug" 等）
- 箇条書きなしの長文本文
- `any` の使用やLint回避のための無意味な変更のコミット
