# 第一原理から再設計する

既存設計に変更を足すとき、ボルトオンしない。その要件が最初からあったかのように再設計する。結果は、1 日目からそれを知っていたら作った形に見えるべきである。

**適用:** 既存コードへ新しい要件を統合するとき。グリーンフィールドの順番は `foundational-thinking.md`（契約先行）。本原則は **後付けパッチの禁止**。

- 影響ファイルをすべて読み、現状の設計を全体として理解する
- 問う: 「ゼロからこの要件込みで書くなら、何を作るか？」
- 変更をすべての参照へ波及させる: 型、docs、例、根拠の記述
- 再設計は holistically に考え、出荷は段階的でよい

既存に足すときにオプション価値を保つ方法である。単位ごとの検証は `sequence-verifiable-units.md`。大きな移行で橋を恒久化しない話は `outcome-oriented-execution.md`。
